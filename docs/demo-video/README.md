## 0. 结论速览

拍一支 **8 分 40 秒、1920×1080 / 30fps、本人普通话讲解 + 全程字幕** 的演示片。

叙事不按"页面清单"平铺，而按 **一个用户的真实使用路径** 串起来：
身份 → 广场 → 发帖 → 互动 → 评论 → 通知 → 分类模块 → 校园服务 → 管理端 → 成绩扩展 → 技术实现。

关键手法有两条：

1. **分段录制、后期拼接**：13 个章节各录各的，一个镜头废了只重录那一段，最终时长可自由裁到 5 分钟版。
2. **每个功能都跟一个"技术佐证镜头"**：JWT 黑名单查 Redis、发图看 MinIO、邮件看 RabbitMQ、限流看 429、缓存看 `topic:preview:*`。这是让评委相信"真是你做的"最有效的手段，比口头说架构强得多。

**现在只剩两件事**（OBS 已于 2026-10-20 装好，版本 32.2.2）：

```bash
# 1) 起环境并自检（实测 ~15 秒三个服务全就绪）
bash scripts/demo-env.sh start && bash scripts/demo-env.sh status

# 2) 录像前备份数据库，拍废了能一键回到起点
bash scripts/demo-env.sh snapshot

# 剪辑器还没装，需要时再装（约 1G）：
flatpak install -y flathub org.kde.kdenlive
```

## 1. 目标、规格与前提

### 1.1 这支片子要解决什么

| 评委的疑问 | 片子里怎么回答 |
|---|---|
| 功能是不是只有登录发帖？ | 13 章覆盖论坛、分类模块、校园服务、管理端、成绩扩展 |
| 是不是套模板 / 是不是你写的？ | 每章一个技术佐证镜头；口播讲清关键实现（树形评论、匿名、限流、黑名单） |
| 有没有真数据、真跑通？ | 全程操作真实后端；发帖/评论/通知都是现场产生 |
| 有没有夸大？ | 主动说明"校园服务非实时对接""成绩是模拟登录 + 快照兜底" |

### 1.2 推荐规格

| 项 | 取值 | 理由 |
|---|---|---|
| 主版时长 | **8:40** | 答辩常见 8–10 分钟；信息密度够，不拖 |
| 精简版 | **5:30** | 超时/初筛用，删"通知收藏 + 成绩 + 校园服务"三章即可 |
| 完整版 | **14:00** | 提交材料用，加资料/隐私设置、找回密码、编辑删除、收藏置顶等 |
| 画幅 | 1920×1080，30fps | 采集 2560×1440 后由 OBS 缩到 1080p，文字更锐 |
| 编码 | H.264 High + AAC 192k | 教室电脑/微信/U 盘都能放，别用 HEVC |
| 声音 | 普通话口播，-12dB 峰值；无人声段垫 BGM | 答辩现场外放，口播必须清楚 |
| 字幕 | 全程硬字幕（关键术语加粗） | 现场音响差也能看懂 |
| 风格 | 深色标题卡 + 浅色系统界面；只做淡入淡出 | 不炫技，重点在功能 |

### 1.3 需要你拍板的 5 件事

1. **时长**：8:40 是否可接受？如果学院卡 5 分钟，我按 5:30 重排（不是简单剪，要换叙事密度）。
2. **口播**：是否本人配音？不配就做纯字幕 + BGM，信息密度要降 30%，节奏要更慢。
3. **成绩模块**：真实学号/姓名/成绩是否入镜？建议学号打码、成绩保留；或只演示到"学期列表"。
4. **工具**：是否同意装 OBS + Kdenlive（约 1.5G，flatpak 用户源已配好）？
5. **答辩日期**：决定第 9 节的倒排时间表；如果只剩 2 天，砍到 5:30 并跳过完整版。

## 4. 分镜与口播

- 逐镜头表：[storyboard.csv](storyboard.csv)（49 个镜头，含时间码、操作、账号、佐证、注意事项）
- 提词器全文：[narration.txt](narration.txt)（按时间码分段，约 1350 字；按 210 字/分钟约 6.5 分钟纯口播，其余时间留给真实操作）

### 4.1 每章的拍法与"证据点"

| 章 | 要证明什么 | 关键镜头 | 技术佐证 | 最大坑 |
|---|---|---|---|---|
| 2 | 系统是三端 + 中间件的真实组合 | 架构图 → `demo-env.sh status` | `docker ps` 四个容器 | 别念端口，图上一目了然 |
| 3 | 认证不是假的 | 注册发码 → 登录 → Network → 登出 | Redis `jwt:blacklist:*` + `ttl` | 邮件延迟/失败；先单独试一次 |
| 4 | 列表是动态加载的 | 切分类 → 滚到底 → 搜索 | `topic:preview:*` 缓存键 | 天气接口超时就跳过 |
| 5 | UGC 真落库、图片真存储 | 富文本 + 插图 → 发布 | MinIO `study` bucket 新对象 | 图片 >5MB 会被拒；提前压到 300KB |
| 6 | 权限/隐私是服务端做的 | 两个账号看同一作者的字段 | 隐私表 + 服务端过滤 | 别让 token 完整长时间入镜 |
| 7 | 评论树与删除规则 | 二层回复 → 删父评论 | `quote`/`root_id`、`allTotal` | 评论 3 秒限流，别连发 |
| 8 | 通知闭环 | qian 互动 → user 未读 → 全部已读 | 通知表 + 未读计数 | 录前别把未读点掉 |
| 9 | 内容模型可扩展 | 失物招领结构化字段 → 已找回 | `extra` JSON 白名单 | 改状态后列表要刷新才更新 |
| 10 | 有业务广度且诚实 | 通知/课程表/图书馆 | 三张表 + 管理端维护 | 必须口播"非实时对接" |
| 11 | 有权限体系 | 锁定/屏蔽 → 切 user 验证 | `ROLE_admin` + 403 守卫 | 别删演示主帖、别封 Admin |
| 12 | 跨栈 + 容错 | 登录 → 学期 → 绩点 | `/grade/api/health`、快照 `offline` | 滑块失败；先预热会话 |
| 13 | 工程细节 | 429 实测 → Redis keys → MQ | 过滤器链、缓存、MQ | 429 会封 30 秒，放最后 |

### 4.2 口播的三个原则

1. **说"做了什么"，不说"用了什么"**：不要念"我用了 Spring Security"，要说"退出后旧 token 立即失效，因为写进了 Redis 黑名单"。
2. **每章开头一句话点题**，结尾不总结（总结放在第 13 章），避免重复。
3. **主动交代边界**：校园服务非实时、成绩服务单账号、Swagger 不可用、图书馆不借阅。评委最烦包装，最喜欢边界清晰。

## 6. 录制执行规范

### 6.1 OBS 参数

| 项 | 设置 |
|---|---|
| 视频 → 基础（画布） | 2560×1440 |
| 视频 → 输出（缩放） | 1920×1080，Lanczos |
| FPS | 30 |
| 输出模式 | 高级 |
| 录像编码 | x264，CQP 20，预设 veryfast，关键帧 2s |
| 录像格式 | **mkv**（断电不坏；剪前再转 mp4） |
| 音频 | 48kHz；轨 1 麦克风，轨 2 桌面音频（可选） |
| 源 | 屏幕采集（XSHM）+ 音频输入采集；麦克风加"噪音抑制（RNNoise）" |
| 快捷键 | F9 开始/停止，F10 暂停 |

场景建议只建 3 个：**浏览器**、**终端**、**图卡**（架构图/标题卡）。切场景比切窗口快，也不容易录到桌面杂物。

### 6.2 操作节奏

- 点击前停 **0.5 秒**，点击后停 **1 秒**再动；剪辑时这些停顿就是切点。
- 鼠标走直线、慢移；不要画圈找按钮。
- 每个章节开头停 1 秒再开始操作，结尾停 1 秒再停录。
- 需要输入的长文本（帖子正文、评论、课程名）**提前写在文本文件里，用 Ctrl+V 粘贴**。
- 每个章节录 **2 条 take**（A/B），后期挑好的；失败不要紧，分段录就是为了这个。

### 6.3 录音

- 优先耳麦/领夹麦；内置麦会有风扇声和键盘声。
- 口播可以**边操作边说**，也可以**先录画面、后配音**。建议后者：操作时不易说错，配音可重录。
- 若后配音：录画面时用手机在开始处拍一下手，后期用波形对齐。
- 每段口播先念标题句，再展开；语速稳定，句间留 0.5 秒。

### 6.4 文件与目录

```
/data/demo-video/
├── raw/          01-intro.mkv … 13-summary.mkv（按章节，A/B 加后缀）
├── edit/         demo-video.kdenlive + 图卡 + 字幕
└── out/          成片 1080p / 720p / 封面
```

命名用 `章节号-英文名-take.mkv`，例如 `07-comments-A.mkv`。别用"未命名 3.mkv"。

## 7. 后期制作

### 7.1 Kdenlive 工程

- 三条轨道：**画面**（主）、**字幕**（SRT）、**BGM/音效**（压低到 -24dB）。
- 章节卡：每章开头 0.6–0.8 秒深色卡，白字章节名 + 序号；只在章节间用 0.3 秒淡入，功能段硬切。
- 角标：右上角常驻"模块名"（如"评论 · 多级树"），换章时更新。
- 放大：点击目标小的时候，用 1.15–1.25 倍关键帧局部放大，比让观众眯眼强。
- 马赛克：学号、邮箱、密码框、二维码；Kdenlive 用"模糊/马赛克"效果跟踪 2–3 秒即可。
- 删掉：加载等待、切窗口、鼠标找按钮、失败重试（除非失败本身是演示点）。

### 7.2 字幕

- 以 [narration.txt](narration.txt) 为底稿，按句切 SRT；一句不超过 20 字，单行不超过 16 字。
- 技术名词保留英文：JWT、Redis、RabbitMQ、MinIO、Quill、ddddocr。
- 关键结论加粗/换色：如"退出后旧 token 立即失效""匿名不是把 uid 置空"。

### 7.3 BGM

- 选无版权、无强旋律的轻电子/钢琴，音量 -24dB 以下；口播段落再压低 3dB。
- 章节切换处不要卡点，避免像营销视频。

### 7.4 导出

| 版本 | 参数 | 用途 |
|---|---|---|
| 主版 | 1080p30，H.264 High，CRF 18–20，AAC 192k，faststart | 答辩播放、提交 |
| 压缩版 | 720p30，CRF 23，AAC 128k | 微信/QQ 发送（控制在 100MB 内） |
| 备份 | 同主版，另存 U 盘 + 网盘 | 现场双保险 |

Kdenlive 直接渲染即可；命令行转码（装了 ffmpeg 的话）：

```bash
ffmpeg -i out/master.mkv -c:v libx264 -preset slow -crf 19 \
  -pix_fmt yuv420p -c:a aac -b:a 192k -movflags +faststart \
  out/20223334_侯学强_校园论坛_功能演示_1080p.mp4
```

> 交付前在**另一台电脑**上试播一次，确认不是只有你这台能放。

## 8. 风险与预案

| 风险 | 概率 | 预案 |
|---|---|---|
| 超星滑块连续失败 | 中 | 录前先登录预热会话（TTL 2h）；准备 2 条 take；实在不行只录到"学期列表"，或演示 `offline` 快照兜底 |
| 邮件验证码延迟/失败 | 中 | 注册段只演示表单与校验，不点发送；或提前录一条成功片段 |
| 天气接口超时 | 低 | 跳过天气卡片，不影响主线 |
| 后端/前端启动失败 | 低 | `demo-env.sh status` 先查；看 `~/.cache/demo-video/run/*.log`；预留 10 分钟 |
| 演示数据被改乱 | 高 | 每章录完 `snapshot`；拍废就 `restore` |
| 麦克风噪声/爆音 | 中 | 耳麦 + RNNoise；试录时看 OBS 音量表，峰值 -12dB |
| 系统通知/更新弹窗 | 中 | 勿扰模式 + 关更新提醒；录前 5 分钟别开新应用 |
| 429 演示把自己封 30 秒 | 高 | 放在最后一段；封了正好念"这里被封 30 秒" |
| 现场播放器不兼容 | 低 | H.264 + AAC + faststart；U 盘 + 网盘各一份；提前在教室电脑试播 |
| 时长超了 | 中 | 按 5:30 精简版剪；或把第 13 章技术总结压到 20 秒 |
